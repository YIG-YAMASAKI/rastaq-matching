# RASTAQ 案件マッチング デモ

クライアントとの画面レビュー・業務フロー確認用の **操作可能なプロトタイプ** です。
バックエンドはなく、すべてフロントエンド内のモックデータで動作します。

- React 18 + TypeScript + Vite / React Router（HashRouter）
- UIライブラリ不使用（`src/styles.css` に共通デザインを集約）
- データはブラウザの localStorage に保存（リロードしても保持。上部バーの「データ初期化」で初期状態に戻る）

## 起動方法

```bash
npm install
npm run dev        # http://localhost:5173/
```

ビルド：`npm run build`（`dist/` に出力。相対パス設定のため静的ホスティングにそのまま配置可）

同じネットワークのスマホから確認する場合は、`npm run dev` 実行時に表示される `Network:` のURLを開いてください。

### GitHub Pages での公開

`main` ブランチへプッシュすると、GitHub Actions（`.github/workflows/deploy.yml`）でビルドされ、以下に公開されます。

https://yig-yamasaki.github.io/rastaq-matching/

- 初回のみ、リポジトリの **Settings → Pages → Build and deployment → Source** を「**GitHub Actions**」に設定してください。
- 公開URLはログイン不要で誰でも閲覧できます（データは閲覧者ごとのブラウザに保存され、他の人には共有されません）。

## 画面構成

画面上部の **デモ切替バー** で以下を行き来できます（ログイン認証なし）。

| 区分 | URL | 主な画面 |
| --- | --- | --- |
| RASTAQ管理画面（PC） | `#/admin` | ダッシュボード / 案件一覧・登録・編集・詳細（応募者比較・手動選定） / チャット / 協力業者管理 / 新規登録審査 / 通知・操作履歴 |
| 協力業者スマホ画面 | `#/sp` | 案件一覧（新着・応募済み・決定・見送り） / 案件詳細・応募・辞退 / 応募履歴 / チャット / 自社情報 |
| 新規登録フォーム | `#/register` | ログイン不要の登録フォーム → 受付完了 |

- スマホ画面のログイン業者は、上部バーのプルダウンで切り替えられます。
- PCではスマホ画面を端末枠で表示し、実際のスマホ幅では全画面表示になります。

## 動作確認の手順（業務フロー）

1. 管理画面「＋案件を登録」で入力 → 「入力内容を確認する」 → 「保存して募集開始へ」
2. 通知先を選択して募集開始（初期状態は未選択。エリア外の業者も候補に表示され、選択すれば通知できます）
3. 「協力業者スマホ画面」→「新着」に案件が届く → 案件を開いて「応募する」
4. 管理画面の案件詳細「応募者・選定」に応募が反映される
5. 「応募を締め切る」→「選定を開始する」→ 決定する業者にチェック →「選定結果を確定して通知」
6. スマホ画面に「選定結果が届いています」と表示され、決定／見送りが反映される
7. 案件詳細の 💬 から質問を送信 → 管理画面「チャット」に未読バッジ → 返信が業者側にも表示
8. 「新規登録フォーム」から申請 → 管理画面「新規登録審査」に反映 → 「承認する」でステータス更新
9. 「通知・操作履歴」で上記の操作がすべて記録されていることを確認

初期データだけでも確認できるよう、選定待ちの案件（新宿区マンション）、手配完了・施工中・完了の案件、見送り済みの応募、未読チャット、審査中の業者2社を用意しています。
ログイン業者を「株式会社アーバンクライム」に切り替えると見送り案件を確認できます。

## 仕様上のポイント

- **自動決定・先着順の決定は行いません。** 締め切り後に、RASTAQ担当者が応募者の中から手動で選定します（複数社の選定可）。
- 条件一致（エリア・工種・熟練度）と距離は **参考表示** です。通知先の自動選択・絞り込みには使いません。
- 決定済みの結果を変更する場合は確認ダイアログを表示し、変更後の結果を通知した扱いにします。
- 難易度レベル5の説明、作業内容と工種の対応表、単価（基本単価・個別単価）は **仮設定** で、画面上にもそう表示しています。
- 交通費は「実費支給」として、案件登録画面と協力業者側の案件詳細に表示しています。

### 案件一覧の表示区分と並び順

| 区分 | 対象ステータス | 標準の並び順 |
| --- | --- | --- |
| 進行中（初期表示） | 募集中・応募締め切り・選定中・手配完了・施工中 | 作業開始日が近い順（同日は更新が新しい順） |
| 下書き | 下書き | 更新日時が新しい順 |
| 完了・中止 | 完了・中止 | 更新日時が新しい順（完了・中止日時は保持していないため、ステータス変更時に更新される更新日時を使用） |
| すべて | 全件 | 進行中 → 下書き → 完了・中止 の順にまとめ、各区分内は上記 |

- 更新日時が無い旧データは登録日時で代替します。並び順のプルダウンで従来の「作業日／締め切り／登録」順にも切り替えられます。
- ダッシュボードからの遷移（`?status=選定待ち` など）は、区分内の追加の絞り込みとして表示します。

### 案件一覧のアラート（管理者向け・並び順や絞り込みには影響しない）

判定は `lib.ts` の `projectAlerts`。下書き・完了・中止は対象外。日時が未設定・不正な場合は判定しません。

| ラベル | 色 | 条件 |
| --- | --- | --- |
| ⚠ 作業日超過・未手配 | 赤 | 募集中・応募締め切り・選定中のまま、作業開始日時を過ぎた |
| ⚠ 締め切り超過 | 赤 | 募集中のまま、回答締め切りを過ぎた |
| ! 作業日接近・未手配 | オレンジ | 募集中・応募締め切り・選定中のまま、作業開始まで3日以内（`START_SOON_DAYS`、仮） |
| ! 要選定 | オレンジ | 応募締め切り・選定中で、辞退以外の応募者がいる |
| ! ステータス未更新 | オレンジ | 手配完了のまま作業開始日時を過ぎた／施工中のまま作業終了日時を過ぎた |

複数該当する場合は最も緊急度の高いラベルだけを表示し、「他N件」と件数を添えます（ラベルにマウスを重ねると全件を表示）。

### 作業内容・対応工種

- 作業内容：シート貼り・安全点検・外壁補修・看板撤去・看板の清掃・その他 の6種類（`src/data/master.ts`）
- 対応工種：既存の14工種に「看板撤去」「看板の清掃」を追加
- 工種一致：作業内容「看板撤去」は対応工種「看板撤去」、「看板の清掃」は「看板の清掃」を持つ業者を一致とします

#### 初期データ（看板系の工種）

| 協力業者 | 看板撤去 | 看板の清掃 |
| --- | :---: | :---: |
| 株式会社スカイライン工業 | ○ | — |
| 有限会社ハイロープサービス | — | ○ |
| 合同会社ベイエリア高所 | ○ | ○ |
| 東都ロープテック・アーバンクライム・武蔵野アクセス・湘南ロープワークス | — | — |

（既存の工種に追加しただけで、その他のプロフィールは変更していません）

#### デモでの確認手順

1. **以前にこのデモを開いたことがあるブラウザでは、まず上部バーの「データ初期化」→「初期化する」を押します。**
   データはブラウザの localStorage に保存されており、保存済みのデータがあると初期データの変更は自動では反映されません（初期化するとデモ中の操作内容は破棄されます）。
2. 管理画面「＋案件を登録」で、作業内容「看板撤去」を選んで入力 → 確認 → 「保存して募集開始へ」。
3. 通知先の選択画面で、スカイライン工業・ベイエリア高所に「✓ 工種」、その他の業者に「× 工種」が表示されます。「全条件一致の業者を選択」を押すと、工種・エリア・熟練度がすべて一致する業者だけが選ばれます。
4. 同じ手順で作業内容「看板の清掃」の案件を登録すると、ハイロープサービス・ベイエリア高所が「✓ 工種」になります。
5. 「協力業者管理」の工種の絞り込みで「看板撤去」「看板の清掃」を選ぶと、対応業者だけを一覧できます。

### 応募者一覧の単価

- 案件に個別単価がある場合：全応募者に案件の個別単価を表示（「個別単価」ラベル）
- 個別単価がない場合：各協力業者の基本単価を表示（「基本単価」ラベル）
- 基本単価も未設定の場合は「未設定」と表示（0円にはしない）。判定は `lib.ts` の `applicantRate`（協力業者側の案件詳細と同じ規則）

### エリア判定（都道府県単位）

- 案件は「作業エリア（都道府県）」と「作業場所住所」を別々に持ちます。
- 協力業者の対応エリアは、都道府県の複数選択または「全国」です（地方ごとの「まとめて選択」は入力の補助）。
- 案件の都道府県が対応エリアに含まれる、または「全国」なら **エリア一致**。対応エリアが空欄の業者は一致しません。
- 募集開始時の通知先は **初期状態で未選択** です。エリア外の業者も候補に表示され（「エリア外」ラベル）、個別選択・「表示中の候補をすべて選択」で通知できます。

### 距離（直線距離・参考）

- 起点は協力業者の住所、終点は集合方法で切り替わります。
  - 現場直行 → 案件の作業場所住所
  - RASTAQ 東京オフィスに集合 → 〒144-0055 東京都大田区仲六郷1-20-6
- 緯度・経度からハバーサイン公式で直線距離を計算し、km・小数第1位で表示します。10km以内は「近場」。
- 一覧は距離の近い順（同距離はエリア一致を先）。距離不明は最後に表示します。
- **座標について（デモの制約）**：外部の地図・ジオコーディングAPIは使っていません。`src/data/geo.ts` の `DEMO_COORDS` に登録した住所だけ座標を持ち、座標は **デモ用の代表座標（測量値ではない）** です。実際の距離とは異なる場合があります。
- 対応表に無い住所は推測せず「距離不明」と表示します（番地まで一致した場合のみ座標を使用。建物名・階の付記や全角・「丁目番地号」表記は吸収）。案件登録画面の住所欄では、座標が登録済みの住所を候補として選べます。
- 初期データでは、審査中の「ロープソリューションズ合同会社」の住所は座標未登録です（承認すると「距離不明」の表示を確認できます）。

### 旧データ（以前のデモで保存したデータ）の移行

読み込み時に自動で移行します（`src/store/migrate.ts`）。

| 旧データ | 移行後 |
| --- | --- |
| 案件の区市（例：東京都港区） | 作業エリア＝都道府県（東京都） |
| 集合方法「RASTAQ指定場所に集合して車で移動」 | 「RASTAQ 東京オフィスに集合」（集合場所の入力文はそのまま） |
| 対応エリア「全国」 | 全国 |
| 北海道・東北・関東・中国・四国・沖縄 | 各地方の都道府県 |
| 近畿 | 2府4県（三重県は定義が分かれるため含めない） |
| 九州 | 7県（旧データでは沖縄が別区分のため） |
| 中部（北部／中央／東海）・その他 | **移行しない**。「全国」などにも変換せず、業者詳細と編集画面に「要再設定」と表示 |

移行内容が不要な場合や表示がおかしい場合は、上部バーの「データ初期化」で初期データに戻せます。

## ディレクトリ構成

```
src/
  types.ts              ドメイン型（案件・業者・応募・チャット・履歴）
  lib.ts                日付整形・距離計算（直線）・エリア一致判定・ステータス算出
  data/master.ts        選択肢マスタ（工種・資格・難易度・集合方法）
  data/geo.ts           都道府県・RASTAQ東京オフィス・デモ用の住所→座標対応表
  data/seed.ts          初期モックデータ（日付は起動時点からの相対値）
  store/AppStore.tsx    全画面共通の状態と操作（localStorage 保存・履歴記録）
  store/migrate.ts      旧形式の保存データの移行
  components/           共通UI（バッジ・ダイアログ・フォーム部品・チャット）
  admin/                RASTAQ管理画面
  partner/              協力業者スマホ画面・新規登録フォーム
```

## 本番実装で対応が必要な箇所

| 項目 | デモでの扱い | 本番で必要な対応 |

| チャット | 画面遷移時に更新 | リアルタイム配信（WebSocket等）、既読管理、添付ファイル |
| 距離・地図 | デモ用の住所→座標対応表から直線距離。未登録の住所は「距離不明」 | 住所ジオコーディング（座標の保存・住所変更時の再取得・取得失敗時の扱い）、必要に応じて経路距離・所要時間API、地図表示 |
| エリア | 案件＝都道府県を手動選択、業者＝都道府県の複数選択 | 住所から都道府県を自動判定するか、手動選択との不一致をどう扱うかの決定 |
| 添付資料 | ファイル名のみ保存 | ストレージへのアップロード、閲覧権限 |
| 応募締め切り | 担当者が手動で締め切り | 締め切り日時での自動締め切り（ジョブ） |
| 新規登録 | 審査一覧に追加のみ | 受付メール、スパム対策、承認時のアカウント発行・契約手続き |
| 単価・難易度定義 | 仮設定 | 単価体系、レベル5の定義、作業内容と工種の対応表の確定 |
| セキュリティ | 対象外 | 入力値のサーバー側検証、監査ログ、個人情報の取扱い |
